# TABANE（タバネ）

クラスの紙を、ひとつの流れに。

Google Classroom の「外」で集める紙――同意書、申込書、各種調査、クラスプリント――の回収確認を、QR コードとスプレッドシート台帳で支えるツールです。

DevFest GDGoC Japan Hackathon 2026（東京会場／教育カテゴリ）提出作品。チーム R2K2（小島 諒・神門 亮太、慶應義塾大学文学部）。

## デモ

- スキャン専用サイト（本番形）：https://tabane.web.app
- Web アプリ版（ハッカソン提出時のフル機能版）：https://qrchecker-533d2.web.app
  - Google 認可なしで試せる「サンプルモード」があります（架空名簿で発行→スキャン→照合まで通せます）

## 解決する課題

学校では今も多くの提出物が紙で回収されています。束になった紙を1枚ずつ名簿と突き合わせる作業は時間がかかり、「誰の紙か分からない」「誰が未提出か分からない」が頻発します。TABANE は、配布物に生徒ごとの QR を載せ、回収した束をまとめてスキャンするだけで、提出・未提出を自動で一覧化します。

## 仕組み

1. **予約する（Google Docs）**
   原稿の Doc で、QR を置く場所を「予約」します（上部の余白に帯を確保し、目印を文書内に残します）。
2. **発行する（台帳スプレッドシート）**
   先生の台帳スプレッドシートから発行します。名簿の生徒×配布物ごとにランダムなトークンを発行し、QR を載せた印刷用 PDF を座席順に生成します。トークンと生徒の対応表は台帳の中にだけあります。
3. **読み取る（スキャンサイト）**
   回収した紙の束をスキャンした PDF を tabane.web.app で読み取り、トークンだけの CSV を書き出します。
4. **確かめる（台帳スプレッドシート）**
   CSV を台帳に取り込むと、回収記録と提出一覧（提出済み／未提出）が自動で作られます。

## 設計のポイント

- **QR に個人情報を載せない**：QR の中身は意味のないランダムトークンだけです。生徒の固定 ID や氏名は入れないので、QR だけから同じ生徒の書類を横断して追うことはできません。対応表は先生の台帳スプレッドシートの中に閉じています。
- **名簿は Web に出ない**：スキャンサイトはアカウント登録・ログインなしで動き、扱うのはトークンだけです。「誰の提出か」の突き合わせは台帳側でのみ行います。
- **生成 AI を使わない**：照合はすべて決定的な処理（QR の読み取りとトークンの一致判定）で行います。再現性のある動作が求められる校務を想定した選択です。
- **先生の Google アカウントで完結**：名簿・記録は先生自身のスプレッドシートと Drive に残ります。開発者側のサーバーに名簿を集約しません。

## リポジトリ構成

| パス | 内容 |
|---|---|
| `src/` | Web アプリ（PaperFlow）のソース。発行・スキャン・照合・記録をブラウザ内で処理します |
| `apps/sheets-ledger/` | 台帳スプレッドシートのスクリプト（Apps Script）。初期設定で名簿／座席表／QR発行／対応表／発行記録／回収記録のタブを作り、発行と CSV 取り込みを担います |
| `apps/docs-addon/` | Google Docs 側のスクリプト。原稿への QR 帯の「予約」だけを行います |
| `scan-web/` | スキャン専用サイト（tabane.web.app）のソース。PDF から QR を読み取り、トークンの CSV を出力します |
| `docs/` | Google 連携のセットアップ手順、テスト計画 |
| `public/licenses/` | 同梱している第三者ライブラリのライセンス文 |

## 技術スタック

- React 19 / TypeScript / Vite
- PDF 処理：pdf-lib、@pdf-lib/fontkit、pdfjs-dist
- QR：qrcode（生成）、jsQR（読み取り）
- フォント：BIZ UDGothic（SIL Open Font License 1.1）
- Google Apps Script（台帳・Docs 予約）、Google Drive API / Sheets API / Classroom API
- Firebase Hosting（配信）

## ローカルで試す

Node.js 24 と npm を用意してください。

```sh
npm ci
npm run dev
```

ブラウザで開き、「サンプルの配布物を作ってみる」を選ぶと、Google 認可なしで架空名簿を使った一連の流れを試せます。Google 連携を使う場合は `.env.example` を `.env.local` にコピーし、`docs/google-setup.md` に沿って設定してください。

スキャン専用サイトは `scan-web/` で同様に起動できます（環境変数は不要です）。

```sh
cd scan-web
npm ci
npm run dev
```

## テスト

```sh
npm test -- --maxWorkers=2
npm run build
```

正常系・異常系・境界値を含むテスト仕様と実行結果は `outputs/` の詳細テスト仕様書（Excel）にまとめています。
