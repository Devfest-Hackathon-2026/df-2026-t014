# TABANE 台帳スプシアプリ（apps/sheets-ledger）

TABANE（TABANE）の本番形である「台帳スプレッドシートにバインドする Apps Script」です。
名簿の読み取りと CSV 取り込み、QR トークンの発行、QR 入り印刷用 Doc／PDF の作成、
スキャン結果 CSV の取り込み、回収状況の突き合わせ、座席表の表示・編集までを、
このスプレッドシートだけで完結させます。

原稿 Doc 側（[`apps/docs-addon/`](../docs-addon/)）の役割は **QR 帯の予約だけ** です。
発行・印刷・回収の記録はこの台帳側が行います。

## セットアップ

1. 台帳用の Google スプレッドシートを新規作成する（1 クラス 1 冊）。
2. スプレッドシートの「拡張機能 → Apps Script」を開き、このフォルダの
   `.gs` / `.html` / `appsscript.json` を取り込む（`clasp push` など）。
3. スプレッドシートを再読み込みし、メニュー **TABANE → 初期設定** を実行する。
4. 「名簿」タブに出席番号・氏名（必要なら生徒ID・座席の行と列）を入力するか、
   メニュー **TABANE → 名簿をCSVから取り込む** を使う。
5. 「座席表」タブでセルに出席番号や氏名を入れて座席を決めるか、「名簿」タブの行・列を直接入力する。
6. 「QR発行」タブの入力欄を埋め、メニュー **TABANE → QRを発行** を実行する。

初期設定は足りないタブだけを作ります。既にあるタブの中身は変更しません。
ただし「名簿」タブに `生徒ID`・`座席の行`・`座席の列` が無い場合は、末尾に列を足します（データ行は変更しません）。
「QR発行」タブが既にあり、空でない場合も上書きしません。

## タブ構成

| タブ | 役割 |
|---|---|
| 名簿 | 出席番号・氏名・生徒ID・座席の行・座席の列。先生が入力する正本。 |
| 座席表 | 名簿の行・列を配置図として表示し、セル入力で座席を編集するビュー。 |
| QR発行 | 発行の入力と出力。固定レイアウト（下記）。 |
| 対応表 | トークンと生徒・配布物の対応（機械用、1生徒1行）。 |
| 発行記録 | 発行ジョブの履歴。再開の判定にも使う。 |
| 回収記録 | 取り込んだスキャン結果（トークン単位）。 |
| 提出一覧_… | 取り込みのたびに新規作成する集計タブ。 |

### 「QR発行」タブの固定レイアウト

A 列が項目名、B 列が値です。A2:A3 の項目名がずれていると、発行は誤読を防ぐため停止します。

| セル | 内容 | 種別 |
|---|---|---|
| A1 / B1 | `項目` / `値` | 見出し |
| A2 / B2 | 原稿DocのURL | 入力（必須） |
| A3 / B3 | 配布物名 | 入力（必須、80文字以内） |
| A4 / B4 | （空行） | — |
| A5 / B5 | 発行日時 | 出力（ISO 8601） |
| A6 / B6 | 発行人数 | 出力 |
| A7 / B7 | 状態 | 出力（`完了` / `途中` / `生成中`） |
| A8 / B8 | メモ | 出力（警告・失敗理由） |
| A9 / B9 | 印刷用PDF | 出力（Drive の URL） |
| A10 / B10 | 印刷用Doc | 出力（Google Docs の URL） |

初期設定を再実行しても、既に新レイアウトなら出力欄の値は消しません。
旧レイアウト（版・ページ数・返却必要ページ・クラス名があった版）の台帳で「初期設定」を実行すると、
B2（原稿DocのURL）と B3（配布物名）を引き継いで新しいレイアウトへ書き換えます。他のタブのデータは変更しません。

### 「名簿」タブ

初期設定で `出席番号`、`氏名`、`生徒ID`、`座席の行`、`座席の列` の見出しを作ります。
列順は問わず、`出席番号` と `氏名` は必須です。`生徒ID` と座席の列は任意です。

- `生徒ID` がある行は、対応表の `studentId` にその値を使います。
- `生徒ID` が空の行は、従来どおり出席番号由来の `n001` 形式を使います。
- 座席（行・列）は 1 始まりです。

### 名簿CSVの取り込み

メニュー **TABANE → 名簿をCSVから取り込む** で、先生の PC から CSV を直接アップロードします。

```
出席番号,氏名,生徒ID,行,列
1,田中 大希,,1,1
2,田中 花子,student-2,1,2
```

- UTF-8（BOM 可）、1 行目が見出し。列順は問いません。
- 必須列は `出席番号`、`氏名`。任意列は `生徒ID`、`行`、`列`。
- 出席番号は 1〜999 の整数で重複不可。氏名は必須。行・列は与えるなら両方とも 1 以上の整数。
- 見出しの判定は名簿タブと同じ `detectRosterColumns_` を使います（`座席の行` / `座席の列` も可）。
- 1 件でもエラー行があれば全体を取り込みません。件数と先頭 5 件の例を表示して止まります。
- 取り込み前に、置き換えであることと人数をダイアログで明示します。
  実行すると **名簿タブのデータ行を CSV の内容で置き換え**、見出し行は保持します。

### 「座席表」タブ

名簿タブの行・列を配置図として表示するビュー兼エディタです。正本は名簿タブの行・列です。

- 1 行目がタイトル、2 行目が説明、3 行目が列番号、4 行目以降が席です。A 列が行番号です。
- 既定は 6 行 × 6 列（36 席）。設定ダイアログで 1〜20 の範囲で変更できます。
- 生徒は `3 田中大希` の形式（出席番号＋氏名）で表示します。同じ席に複数いれば改行で並べます。
- セルに出席番号または氏名を入れると、その生徒の行・列を名簿へ記録します。
  - 出席番号の完全一致（全角数字は正規化）
  - 氏名の前方一致で候補が 1 人だけなら確定
  - 候補が 0 人・複数人のときは記録せず、セルを赤くしてメモを残します。
  - 空にすると、その席の生徒の座席指定を解除します。
  - 既に別の席にいる生徒を確定すると移動として扱い、元のセルは空になります。
  - 既に別の生徒が確定しているセルに確定すると、同じ席に複数人として表示します（同席はエラーにしない）。
    入れ替えたいときは、一度セルを空にしてから入れてください。
- 名簿タブの行・列を直接変えた場合も、座席表を描き直して反映します（双方向同期）。
- グリッドの外に出た生徒は描画できません。座席表の 2 行目と再描画・設定保存時のメッセージで人数と名前を知らせます。
- 印刷用に列幅・行高・罫線・タイトル行を設定し、グリッド線は非表示にしています。

### 「対応表」の列

1 生徒 1 行です。列順は固定です。

```
token, collectionId, versionId, studentId, kind,
studentNumber, studentName, title, jobId, issuedAt
```

- `kind` は `content`。
- `token` は 32 桁の 16 進小文字。QR の中身はこの文字列そのもの。
- `collectionId` / `versionId` は発行ごとのランダム値。`jobId` は再開のキー。
- 生徒 1 人処理するごとに対応表へ追記する。途中で止まっても発行済みトークンは残る。

### 「発行記録」の列

```
jobId, status, title, sourceDocumentId,
collectionId, versionId, studentCount, doneStudents, tokenCount,
layoutMode, qrCorner, bandHeightPt, issuedAt, updatedAt,
printDocumentId, printDocumentUrl, pdfFileId, pdfUrl, note
```

- `status` は `生成中` → `完了`（組み立て失敗時は `途中`）。
- `layoutMode` は `reserved-corner`（原稿が予約済み）または `management-band`（未予約）。
- 同じ原稿 Doc に未完了の記録が残っている場合、次回の「QRを発行」はそのジョブを自動で再開します。
  入力を変えて新規発行したいときは、先に未完了ジョブを完了させるか、記録の状態を確認してください。
- 旧形式（`versionLabel` / `className` / `pageCount` / `printPageEstimate` を含む）の行が残っていても、
  見出し名で列を探すため再開できます。旧形式の対応表にページ別トークンが残っている場合は、
  生徒ごとに先頭の 1 つだけを再利用します。

### 「回収記録」の確定列

```
token, collectionId, studentId, studentNumber, studentName, pageNumber,
status, scanId, scannedAt, sourceFile, importedAt, note
```

`status` は次の値です。

| 値 | 意味 |
|---|---|
| `ok` | 対応表に存在するトークンを読み取り、回収として記録した |
| `unknown` | 読み取れたが対応表にないトークン（要確認） |
| `unreadable` | QR を読み取れなかった（要確認） |
| `duplicate` | 同一スキャン内で重複し要確認になった（回収済みとは扱わない） |

`pageNumber` は CSV 行の `page`（QR が読まれたスキャン上のページ）です。対応表にないトークン・読み取り不可の行も同様です（元ファイルは `sourceFile` / `note` から追えます）。

同じ CSV を再取り込みしても、`ok` はトークン単位、それ以外は
`scanId + sourceFile + pageNumber + token + status` の組で重複を判定し、二重に記録しません。
記録を増やさなかった要確認行も、提出一覧の `要確認` には再掲します。

## QR結果の取り込み（CSV 接合部）

### 形式（この定義が正本）

- UTF-8、カンマ区切り、1 行目がヘッダー。改行は LF／CRLF の両方に対応。
- 引用符は RFC 4180 形式（`"` のエスケープは `""`、引用符内の改行・カンマ可）。
- ヘッダーは列名で判定する。順序違いは許容し、不足・余分・重複はエラー。
- 1 行 = 回収 PDF の 1 ページ分の結果。

```
scan_id,scanned_at,source_file,page,token,status,note
```

| 列 | 意味 |
|---|---|
| `scan_id` | スキャンセッションの識別子（文字列） |
| `scanned_at` | 読み取り日時（ISO 8601） |
| `source_file` | 元の回収 PDF のファイル名 |
| `page` | PDF 内ページ番号（1 始まりの整数） |
| `token` | 読み取ったトークン文字列。読取不可の行は空 |
| `status` | `ok` / `unreadable` / `duplicate` |
| `note` | 要確認の理由など（任意、空可） |

壊れた行（列数違い、日時でない `scanned_at`、整数でない `page`、未知の `status`、
`ok` なのに `token` が空、など）はスキップし、件数と先頭例を結果に返します。
ヘッダー不一致は取り込み全体を停止します。

### 取り込み方法

roadmap の文面は「Drive から選んで取り込み」ですが、この実装では
**ダイアログで先生の PC から CSV を直接アップロード**します。

理由:

- スキャン道具からダウンロードした CSV を Drive へ上げ直す手順は先生にとって無駄が多い。
- Picker 方式はテンプレートコピー配布だと各コピーに API キー設定が必要で現実的でない。
- `drive.file` は作成したファイルにしか効かず、先生が手で上げた CSV を Picker で選ぶには
  Drive 全体のスコープが必要になる。直接アップロードなら Drive スコープを増やさずに済む。

メニュー **TABANE → QR結果を読み取る** でダイアログを開き、CSV を選んで「取り込む」を押します。
サーバー側では `importTABANEScanCsv({ fileName, text })` が動きます。

### 提出一覧タブ

取り込みのたびに `提出一覧_<配布物名>_<取り込み日時>` を作ります。
新規に追記する行が 0 件の再取り込みでも、CSV に含まれる配布物のタブを作り、累積の状態を表示します。
CSV が複数の配布物にまたがる場合は、対応表の `collectionId` ごとにタブを分けます。
対応表で特定できない行（未知トークン、読み取り不可）だけの場合は
`提出一覧_未分類_<取り込み日時>` を作ります。

タブの内容:

- 配布物名・取り込み日時
- 出席番号・氏名・`まとめ`（`提出済み` / `未提出` の2値）
- `集計`: 提出済み n 人 / 未提出 n 人
- `要確認`: 種別・トークン・ページ（スキャン上のページ）・元ファイル・理由

判定は今回の CSV だけでなく、**対応表と回収記録の累積**から行います。
たとえば未提出だった生徒のトークンを後日取り込むと、2 回目のタブでは `提出済み` になります。
ページ単位の回収は判定に使いません（QR は生徒 1 人につき 1 つ）。

## 発行処理の詳細

1. 「QR発行」タブの入力を読む。
2. 原稿 Doc を URL から `DocumentApp.openById` で開く（アクティブ文書ではない）。
3. 単一タブ・A4縦を検査し、`PFQR1_...` マーカーを名前付き範囲とヘッダーから検出する（検出のみ）。
4. 名簿タブ（設定で別スプレッドシートを指定した場合はそちら）を読み、次の確定ルールで並べる。
   1. 座席（行・列）のある生徒を先に、行→列の昇順
   2. 座席のない生徒を後ろに、出席番号の昇順
   3. 全員に座席がなければ出席番号順
   4. 同じ行・列に複数いれば出席番号順で安定させる（エラーにしない）
5. 生徒 1 人につきトークンを 1 個発行し、対応表へ逐次記録する。
6. `QrCode.gs`（qrcode-generator 1.4.4 同梱）と `QrImage.gs`（自前 PNG 化）で QR を作る。
   外部 API は呼ばない。
7. 生徒ごとに「出席番号・氏名・配布物名」と QR 1 つを先頭へ置き、原稿本文をコピーして印刷用 Doc を作る。
   PDF 化してから Doc を閉じ、Drive の出力フォルダへ Doc と PDF を保存する。
8. 発行記録を更新し、「QR発行」タブの出力欄へ PDF・Doc のリンク、発行日時、人数、状態を書く。

出力フォルダは初回発行時に自動作成し、その ID をスクリプトプロパティに保存します。
以後は ID で開くため、先生が Drive 上でフォルダを移動・名前変更しても同じフォルダへ出力し続けます。
設定でフォルダ名を変えたときだけ、新しい名前のフォルダを作り直します。
（`drive.file` スコープではフォルダの名前検索ができないため、コード内で名前検索は使いません。
また、組み込みサービスのフォルダ作成は `drive` 全体の権限を要求するため、フォルダ作成・移動・PDF 保存は
Drive 高度なサービス（Drive API v3）で行います。）

制約:

- 印刷用 Doc へコピーするのは本文要素のみ。原稿のヘッダー・フッターは引き継がない。
- QR は生徒ごとに 1 つ。印刷方式上、生徒の全ページ分の QR を先頭 1 枚にまとめる必要がないため、
  ページ単位の回収判定は行わない。
- 未予約の原稿は管理帯方式（上余白を足して QR 帯を置く）で組み立てる。本文のページ数が増えることがある。
- 1 回の発行は 60 人まで。
- 中断時は発行記録が完了以外のまま残る。再開すると、発行済みトークンと作成済みの印刷用 Doc を再利用し、
  トークンの二重発行・印刷用 Doc の作り直しをしない。PDF の保存だけ失敗したジョブは、既存の印刷用 Doc から
  PDF を作り直して続行する。

## テンプレート用に初期化

配布用テンプレートを作るときは、開発用台帳のコピーでメニュー
**TABANE → テンプレート用に初期化** を実行します。実行前に、消えるものを列挙した確認ダイアログが出ます。

- 空にする: 「名簿」「対応表」「発行記録」「回収記録」のデータ行（見出しは残す）
- 空にする: 「QR発行」タブの B2:B10（A 列の項目名は残す）
- 削除する: 「提出一覧」で始まるタブ
- 描き直す: 「座席表」を空の名簿から再描画
- 初期値に戻す設定: 名簿スプレッドシートのURL、名簿タブ名
- 消す内部設定: 出力フォルダの ID・作成時のフォルダ名（次に発行したときに作り直されます）
- 残す設定: 未予約原稿のQR位置、帯の高さ、出力フォルダ名、座席表の行数・列数
- 残すもの: タブ構成、見出し、書式、スクリプト

名簿の参照先が別スプレッドシートに設定されていた場合、その外部名簿は変更しません。タブ構成・見出し・書式は壊さず、データ行だけを `clearContent` で空にします。

## 設定

メニュー **TABANE → 設定**。保存先はスクリプトプロパティです。

| 項目 | 既定値 | 用途 |
|---|---|---|
| 名簿スプレッドシートのURL | 空（台帳本体） | 名簿が別スプシにある場合の参照先 |
| 名簿タブ名 | `名簿` | 参照するタブ |
| 未予約原稿のQR位置 | `top-right` | 管理帯方式のときの記録用 |
| 未予約原稿の帯の高さ（pt） | `96` | 管理帯方式の余白・QRサイズ |
| 出力フォルダ名 | `TABANE 発行` | 印刷用 Doc／PDF の保存先。初回発行時にこの名前でフォルダを作り、以後は ID で追う |
| 座席表の行数 | `6` | 座席表グリッドの行数（1〜20） |
| 座席表の列数 | `6` | 座席表グリッドの列数（1〜20） |

座席表の行数・列数を変えて保存すると、座席表を描き直します。
新しいグリッドの外に出る生徒がいれば、設定ダイアログに人数と名前を表示します。

出力フォルダの ID（`outputFolderId`）と作成時のフォルダ名（`outputFolderCreatedName`）は内部項目で、
設定ダイアログには表示しません。フォルダの解決は次の順です。

1. 設定の「出力フォルダ名」が作成時の名前と違う → 新しい名前でフォルダを作り、ID と作成名を更新する。
2. ID があり `Drive.Files.get` で開けて、ゴミ箱に入っていない → そのフォルダを使う。
3. ID がない・開けない・ゴミ箱 → フォルダを作り、ID と作成名を保存する。

Drive 上でフォルダを移動・改名しても、設定の「出力フォルダ名」を変えない限り作り直しません。

## スコープ

`appsscript.json` で要求するのは次の 4 つです。バインド型のまま（`addOns` は追加しない）。

| スコープ | 理由 |
|---|---|
| `spreadsheets` | 台帳本体の読み書きと、設定で指定された別スプレッドシートの名簿読み取り。 |
| `documents` | 原稿 Doc を URL から開く。印刷用 Doc を新規作成し、本文要素をコピーする。 |
| `drive.file` | このスクリプトが作成した印刷用 Doc と PDF の保存・移動。Drive 全体は要求しない。 |
| `script.container.ui` | メニューから CSV 取り込み・設定のモーダルダイアログを表示するため。 |

Drive のファイル・フォルダ操作には Drive 高度なサービス（v3）を使います。
`appsscript.json` の `dependencies.enabledAdvancedServices` に `Drive` を宣言していますが、
上の 4 スコープは変えていません（`drive` は要求しません）。

## テスト

`Code.test.ts` は SpreadsheetApp／DocumentApp／Drive（高度なサービス）／Utilities をモックし、
`runInNewContext` で `.gs` をまとめて実行します。カバー範囲:

- 初期設定（タブ・見出しの作成、既存タブを壊さない、名簿の不足列を足す、旧QR発行レイアウトの移行）
- 名簿パースと並び順（全員座席あり／混在／全員座席なし／同席のタイブレーク）
- 名簿CSVの取り込み（列順・BOM・生徒ID・座席、置き換え、エラー時の全体停止）
- 座席表の解決ロジック（番号一致・氏名の前方一致・曖昧・該当なし）
- 座席表の編集（確定・移動・解除・重複検出）と名簿側編集の反映
- グリッド外の生徒の通知
- 別スプシ参照（名簿）
- 予約マーカーの検出（名前付き範囲・ヘッダー）
- トークン形式・一意性、QR PNG 生成
- QR発行の入力2項目と必須検証、1生徒1トークン、生徒ヘッダー文面、対応表・発行記録の新スキーマ
- 発行と固定レイアウト出力
- 出力フォルダの解決（初回作成・ID 再利用・Drive 上の改名では作り直さない・ゴミ箱／取得失敗時の作り直し・設定名の変更）
- 再開時のトークン重複なし、PDF 保存だけ失敗したジョブの再開（印刷用 Doc を作り直さない）
- 旧列が残る未完了ジョブからの再開
- CSV パース（正常系・ヘッダー不一致・壊れた行）
- 突き合わせ（既知・未知・二重取り込み）
- 提出一覧の判定（提出済み・未提出のみ）と累積判定、旧データの1生徒複数トークン
- テンプレート用の初期化（データ行の消去、見出しの保持、提出一覧タブの削除、開発用設定の初期化、新クリア範囲）

実行:

```
npm test
```
